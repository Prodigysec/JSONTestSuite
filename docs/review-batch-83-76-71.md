# Headless browser and value observations: #83, #76, #71

Reviewed on 2026-10-03. Upstream [#83](https://github.com/nst/JSONTestSuite/issues/83) requests tests in major browser engines, while [#76](https://github.com/nst/JSONTestSuite/issues/76) asks how parsers handle positive and negative zero and [#71](https://github.com/nst/JSONTestSuite/issues/71) asks whether they collapse case-distinct object names. All three issues remain open and have no proposed PR revision. Earlier batches added the four exact transformation fixtures and compared Python and Node/V8 values; this batch adds a real headless Chromium browser context.

Build `jsonsuite-chromium:local` with `docker build -f Dockerfile.chromium -t jsonsuite-chromium:local .`. The Linux x86-64 image uses the digest-pinned PHP 8.3.27 Bookworm base and Debian Chromium `154.0.8037.92-1~deb12u1`; PHP is only a base-image convenience. The installed Debian package retains Chromium's license notices. APT dependencies are not snapshot-pinned, so rebuilds can change their revisions. Docker, Python 3, and the built image are required to invoke the `Chromium 154.0.8037.92 JSON.parse (headless)` registry mode. The adapter creates an ephemeral HTML page, base64-encodes the original fixture bytes only for transport, and has Chromium reconstruct those bytes. The browser uses fatal UTF-8 decoding with BOM retention and calls `JSON.parse` on one complete text. The page returns a JSON result marker; missing markers, Docker failures, browser failures, and missing files return adapter status 2. A missing image is skipped by the runner's setup check. Both container execution and the wrapper have time bounds.

Smoke checks accepted `null` and `0e+1`, rejected an extra comma, trailing `#`, malformed UTF-8, and the UTF-8 BOM, and returned 2 for a missing path. The BOM fixture is implementation-dependent under RFC 8259 §8.1; the browser's rejection is an observation, not a corpus reclassification. `python3 -B survey_chromium.py > /tmp/jsonsuite-chromium-327.jsonl` logged every fixture's result from one browser page. That survey reconstructed each fixture's bytes and used the same decoder and `JSON.parse` call as the adapter. It left tracked reports untouched:

A separate per-fixture registry-command survey reached 100 fixture invocations, then was stopped because browser startup dominated runtime. It did not retain per-case results, so it is **not** a completed 327-case adapter run. The JSON Lines file from the one-page survey contains all 327 browser-engine outcomes, but does not establish that every registry invocation completes within the runner's five-second limit. The smoke checks and focused regression tests exercise the adapter path.

`python3 -B run_transform.py` now includes the browser alongside Python and Node/V8 for the four value fixtures. Chromium retained the parsed sign of `[0.0]` (`5b 30 2e 30 5d 0a`) and `[-0.0]` (`5b 2d 30 2e 30 5d 0a`), but serialized both as `[0]`. RFC 8259 §6 permits the negative-zero spelling without requiring sign preservation after parsing or serialization. Chromium also retained both `a` and `A` members, in source order, for `{"a":1,"A":2}` and its reversed companion. RFC 8259 §§4 and 8.3 distinguish unique names and code-unit comparison; the fixtures' bytes remain unchanged. These are value observations, not general compliance verdicts. The remaining 22 transformation inputs and Firefox or WebKit browser contexts remain outside this command.

The pinned image built and reported Chromium 154.0.8037.92 on Debian Bookworm. Focused adapter tests cover result markers, image unavailability, and exit-code mapping. The regression suite passed 80 tests with 21 optional skips, and `git diff --check` passed. No tracked historical report or fixture changed.
