# JavaScriptCore, JSON Spirit, and tool inventory: #83, #21, #41

Reviewed on 2026-10-03 against upstream [#83](https://github.com/nst/JSONTestSuite/issues/83), [#21](https://github.com/nst/JSONTestSuite/issues/21), and [#41](https://github.com/nst/JSONTestSuite/issues/41). All three remain open and have no PR revisions to integrate. #83 requests distinct JavaScript engines, preferably browser engines; #21 requests broader C++ JSON parsers; #41 requests a container with required software and its discussion calls for a program list first.

`JavaScriptCore 2.50.6 JSON.parse (strict UTF-8)` adds WebKit's JavaScriptCore shell as a distinct engine. Build its Linux x86-64 environment with `docker build -f Dockerfile.jsc -t jsonsuite-jsc:local .`. The image uses the digest-pinned PHP 8.3.27 Bookworm base already used by this fork and Debian's `libjavascriptcoregtk-4.0-bin` and library packages at `2.50.6-1~deb12u2`. PHP is only a base-image convenience; the tested parser is JavaScriptCore's `JSON.parse`. Debian's package retains its upstream licensing and notices. The runner invokes `python3 parsers/test_jsc.py FILE`; the wrapper checks the original bytes as strict UTF-8, then bind-mounts the checkout read-only and calls `jsc` on the original path. The shell's `readFile` preserves the UTF-8 BOM but replaces malformed bytes, which is why the wrapper rejects malformed UTF-8 before invoking it. The shell's `quit(1)` returns process status 0, so an explicit result marker is required to distinguish acceptance from rejection. Missing files or images, unexpected shell output, and runtime failures return 2. Both the wrapper and the container bound execution time. This mode exercises a browser engine's shell, not a full browser; Chromium and Firefox comparisons remain pending.

`C++ JSON Spirit c7245a39` adds [ciere/json_spirit](https://github.com/cierelabs/json_spirit) at commit `c7245a39c94071804dcd1838d84415788c7f2c29` (Boost Software License 1.0). `sh parsers/build_json_spirit.sh` downloads SHA-256-verified source (`8ea54b9e75bece24ea776a28f292a0192fa73ced6bd48ce8e78931773c857f68`) and Ubuntu's Boost 1.74 headers (`97b0544205439a6073bf13e7df7b0f29d7363241115ee59011c0dcba2adb75b6`), preserving both in ignored `parsers/.build/`. It needs curl, tar, sha256sum, dpkg-deb, and a C++17 compiler. It was built on Linux x86-64 with isolated GCC 13.3 and invoked as `parsers/.build/json-spirit/test_json_spirit FILE`. The adapter reads raw bytes and calls `construct(input, value, true)`; `true` requires whole-input consumption. It exits 2 on file or unexpected adapter errors. The source license remains in its extracted tree.

The smoke checks covered `null`, `0e+1`, an extra comma, trailing `#`, malformed UTF-8, a UTF-8 BOM, and a missing file. Both adapters accepted the valid scalars, rejected the malformed cases and BOM, and returned 2 for missing input. The full 327-case surveys used the registry commands directly with a five-second per-case limit, leaving historical reports untouched:

| Mode | Expected `y_`/`n_` | `i_` accept / reject | Unexpected acceptance / rejection | Crash | Timeout |
| --- | ---: | ---: | ---: | ---: | ---: |
| JavaScriptCore | 288 | 25 / 14 | 0 / 0 | 0 | 0 |
| JSON Spirit | 271 | 28 / 11 | 15 / 0 | 2 | 0 |

JSON Spirit's 15 unexpected acceptances are malformed numbers, including `n_number_-2..json` (`5b 2d 32 2e 5d`, `[-2.]`) and `n_number_NaN.json` (`5b 4e 61 4e 5d`, `[NaN]`). RFC 8259 §6 requires digits after a decimal point and does not include NaN. The parser segfaulted (exit `-11`) on `n_structure_100000_opening_arrays.json` (100,000 `5b` bytes) and `n_structure_open_array_object.json`; these remain crashes, not JSON rejections. The second case and crash behavior are observations of the pinned implementation, not fixture reclassifications.

For #41, `python3 -B inventory_parser_tools.py` now emits a JSON record for every registry mode with its first-stage executable, resolution on the current `PATH`, and any setup command. On this host it listed 117 modes, 43 without a resolvable first-stage executable. This is an executable inventory, not proof that 74 modes are runnable: modules, container images, platform-specific binaries, and nested dependencies still require checks. The scoped `Dockerfile.core` and `Dockerfile.jsc` environments remain partial; a universal image across macOS-only and Linux tools is not claimed.

The pinned JavaScriptCore Dockerfile rebuilt successfully; the JSON Spirit build and all adapter smoke checks passed. The Python regression suite passed 76 tests with 21 optional skips, including focused checks for JavaScriptCore's result marker and malformed-byte preflight. `git diff --check` passed. No parsing fixture or tracked historical report changed.
