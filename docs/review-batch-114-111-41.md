# Rust, PHP, and container environment review: #114, #111, #41

Reviewed on 2026-10-03 against upstream [#114](https://github.com/nst/JSONTestSuite/issues/114), [#111](https://github.com/nst/JSONTestSuite/issues/111), and [#41](https://github.com/nst/JSONTestSuite/issues/41). All three remain open upstream. #114 has no discussion and asks for modern Rust JSON coverage after `rustc-serialize` was deprecated. #111 asks for PHP 7 results because PHP's parser changed from PHP 5. #41 asks for an environment containing all needed software; its sole comment suggests first listing the programs. These are issues, not proposed PR revisions.

Local integration commit: `e1e6137`.

The checkout already registered a `serde_json` adapter, but its Cargo dependency was `*`, its README contained a machine-specific path, and no lockfile was tracked. It also printed input and returned JSON rejection for file I/O failures. The adapter now pins `serde_json =1.0.145` and its transitive dependencies in `Cargo.lock`, reads bytes without preprocessing, checks one complete JSON text with `from_slice`, and exits 2 for invocation or file failures. The `Rust serde_json 1.0.145` registry mode uses a source-built binary in ignored `parsers/.build/`. The older `rustc-serialize` and `json-rust` entries remain for historical comparison. Run `docker pull rust@sha256:3914072ca0c3b8aad871db9169a651ccfce30cf58303e5d6f2db16d1d8a7e58f` and then `sh parsers/build_rust_serde_json.sh`. The script uses Rust 1.90.0 on Linux, builds with `cargo build --locked`, and requires Docker plus access to crates.io on a cold cache. The `serde_json` crate is under MIT or Apache-2.0; its source and license are fetched by Cargo, not vendored here.

The historical `PHP 5.5.36` registry entry remains unchanged as a historical label. The new `PHP 7.4.33 Docker` and `PHP 8.3.27 Docker` entries use the official PHP CLI images at digests `sha256:620a6b9f4d4feef2210026172570465e9d0c1de79766418d3affd09190a7fda5` and `sha256:01224f5f2e75fa43a326797d7b80552ca0bcfb37f60cbb81efdf63956b4d3fe4` respectively. Pull those images before a run. The runner bind-mounts this checkout read-only at its absolute path and calls the same `json_decode` adapter; no BOM removal or decoding replacement occurs. The adapter now exits 2 on missing input. The PHP 7.4 entry answers #111 with a reproducible late-PHP-7 mode; it does not characterize every PHP 7 release.

`Dockerfile.core` is a tested first container profile for #41: digest-pinned PHP 8.3.27 and Rust 1.90.0 images plus Debian Bookworm Python 3.11 from APT. Build with `docker build -f Dockerfile.core -t jsonsuite-core:local .`; test a fixture with `docker run --rm --network none --mount type=bind,src="$PWD",dst=/suite,readonly jsonsuite-core:local php parsers/test_json.php test_parsing/y_structure_lonely_null.json`. It is a starting environment, not an all-parser image. The current registry has 115 modes using Java, Perl, Python, PHP, Rust, .NET, R, Lua, Node, native C/C++, Swift, VHDL, Docker and other executables; several historical Objective-C/macOS binaries cannot run as native Linux programs. Debian APT is not snapshot-pinned, so rebuilding this profile can change the Python package revision. Per-platform profiles and a machine-readable dependency inventory remain for #41.

Smoke checks used `null`, `0e+1`, an extra comma, trailing `#`, malformed UTF-8, a UTF-8 BOM, a 500-level nesting case, and a missing path. The adapters accepted the valid scalars, rejected the malformed syntax and bytes, and returned 2 only for the missing path. The BOM case is implementation-dependent and all three modes rejected it. The full 327-case surveys ran directly from the registry commands with a five-second per-case bound and did not touch tracked historical reports.
