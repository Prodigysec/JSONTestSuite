# Runner verdict, transformation survey, and tool inventory: #131, #76, #41

Reviewed on 2026-10-03 against upstream [#131](https://github.com/nst/JSONTestSuite/issues/131), [#76](https://github.com/nst/JSONTestSuite/issues/76), and [#41](https://github.com/nst/JSONTestSuite/issues/41). All three issues remained open. These are follow-ups to earlier local integrations, not new claims that an open issue proves a remaining defect. Implementation commit: `dd91a28`.

For #131, expected-result rows and explicit skips were already integrated locally. The remaining runner gap was a useful process verdict for automation. `run_tests.py --fail-on-discrepancy` now exits 1 for unexpected `y_`/`n_` outcomes, crashes, timeouts, or either skip status. An `i_` acceptance or rejection is allowed, but its crash or timeout fails. The default historical exit policy remains zero after a completed run; invalid selections still exit 2. The runner counts statuses as it records the fresh run, so this verdict does not rely on an archived or incomplete report. Both reports are generated before the CLI returns. This is a completed local follow-up, not a change to the upstream issue's original requested report rows.

For #76, the existing four focused value probes remain the default. `run_transform.py --all` now observes all 26 files in `test_transform/` using Python, Node/V8, and Chromium when its image is built. Each record contains parse status, runtime value type, and serialized text. For example, the exact `[-0.0]` fixture (`5b 2d 30 2e 30 5d 0a`) is parsed as a negative floating zero by the focused probe; the full survey shows Python serialization `[-0.0]` and JavaScript serialization `[0]`. RFC 8259 §6 permits the input spelling but imposes no serialized representation for an in-memory value. Rejections in the broad survey are observations, not acceptance-test verdicts. It does not assert that serialization preserves source bytes or that runtimes agree on all values. A missing Chromium image is reported as unavailable.

For #41, `inventory_parser_tools.py` now reports the setup command's first executable and whether it resolves, separately from the invocation executable. On this Linux x86_64 host, the inventory lists 118 registry modes, 43 with an unresolved invocation executable, and 3 of 10 setup commands with an unresolved first executable. This checks only the first program in each command; it cannot establish nested module availability, platform compatibility, container images, or successful builds. The scoped Docker images remain partial; a universal all-parser environment is pending.

The 26-file transform survey completed with 23 parses and 3 rejections for each of Python, Node/V8, and Chromium; none reported an observer error. A fresh full-corpus runner check of Perl 5.38.2 / JSON::PP 4.16 on Linux x86_64 recorded all 327 selected cases (288 expected results, 19 implementation-dependent accepts, 20 implementation-dependent rejects) and returned CI verdict 0. Its logs and reports were written under a temporary directory. `git diff --check` passed; no fixture bytes or tracked historical reports changed.
